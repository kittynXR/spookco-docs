Development field notes · Publishing

Updating this site

One normal project push

The canonical website source lives at Docs/site/ in the main SpookCo repository. Edit the Markdown in Docs/site/content/, commit it with the rest of the project, and push main. The Publish documentation GitHub Action builds and checks the site, then copies only the generated website into the separate kittynXR/spookco-docs repository. GitHub Pages serves that repository at spookco.kittyn.cat.

There is an ignored local checkout at Docs/site-repo/ for inspecting the deployment repository. It is not a submodule and does not need to be committed from the game repo. Do not author content there: the next publish replaces generated pages. No Unity assets, client logs, player data, or game source are copied to the public docs repository.

The existing engineering reports outside Docs/site/ remain project documentation. They are not blindly mirrored to the public site. Update the curated status/testing pages when a new result supersedes an older one. Label results as implemented, locally checked, user confirmed, or open; include the tested build and date when available.

Preview locally

From Docs/site/, create a Python 3.12+ virtual environment, install requirements, then run:

python -m pip install -r requirements.txt
python build.py
python check.py
python -m http.server 8765 --directory _build --bind 127.0.0.1

Open http://127.0.0.1:8765/ and /internal/. The build output and local environment are ignored by Git. The Action uses the same build/check commands before publication.

Publishing and credentials

The publishing Action runs for changes under Docs/site/** or its workflow, and can be run manually. It has read-only access to the main repo and uses a dedicated SSH deploy key with write access only to the docs repository. The private key is stored in the main repo’s SPOOKCO_DOCS_DEPLOY_KEY Actions secret. Never put its contents into source, Markdown, or logs. SSH host verification uses GitHub’s pinned Ed25519 host key.

The docs repository publishes generated files from main at the repository root, with a .nojekyll file and CNAME containing spookco.kittyn.cat. Each deployment records the source revision in build-info.json. A failed build/check stops before replacing the deployed site; pushes are normal fast-forward updates with no force push.

If publication fails, inspect the main repo’s Action first, then the docs repo’s Pages build/deployment. Confirm the deploy key still exists and the custom domain points to GitHub Pages. Cloudflare proxy/certificate changes can affect HTTPS independently of a successful site build.

Public versus internal

Player pages, player navigation, the public search index, and sitemap contain no links to /internal/. Internal pages have their own navigation/search and noindex, nofollow metadata. This is discoverability separation, not authentication. Someone with the URL can read or share the pages, and the generated docs repository is public.

Do not publish secrets or sensitive operational details here. If actual private team documentation becomes necessary, put it behind authentication instead of relying on an unlisted path.

Platform references

Publishing follows GitHub’s Pages publishing-source documentation, custom-domain setup, and deploy-key documentation.
